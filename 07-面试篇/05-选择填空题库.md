## 选择题

### 1.（Java基础·易）JDK、JRE、JVM 三者的包含关系是？
- A. JDK ⊃ JRE ⊃ JVM
- B. JVM ⊃ JRE ⊃ JDK
- C. JRE ⊃ JDK ⊃ JVM
- D. 三者互相独立

答案：A
解析：JDK = 开发工具 + JRE，JRE = JVM + 核心类库；只需运行程序装 JRE，要开发才装 JDK。详见《01-入门篇/01-环境搭建与基础语法.md》

### 2.（Java基础·中）`StringBuilder sb = new StringBuilder("a");` 调用 `change(sb)`，方法体为 `void change(StringBuilder x){ x.append("b"); x = new StringBuilder("c"); }`，之后 sb 的内容是？
- A. a
- B. c
- C. ab
- D. bc

答案：C
解析：Java 只有值传递：append 修改的是同一个对象，而重新赋值只改变了形参的指向，不影响实参。详见《01-入门篇/02-面向对象与核心类.md》

### 3.（Java基础·易）`Integer a = 127, b = 127; System.out.println(a == b);` 输出什么？
- A. false
- B. 编译错误
- C. 不确定
- D. true

答案：D
解析：IntegerCache 缓存 -128~127，范围内 == 比较的是同一个缓存对象；超出范围（如 128）必须用 equals。详见《01-入门篇/02-面向对象与核心类.md》

### 4.（Java基础·易）以下哪个不属于面向对象三大特性？
- A. 重载
- B. 封装
- C. 继承
- D. 多态

答案：A
解析：三大特性是封装、继承、多态；重载是编译期确定同签名不同参数的方法，不属于三大特性。详见《01-入门篇/02-面向对象与核心类.md》

### 5.（Java基础·易）try-with-resources 的主要作用是？
- A. 自动提交事务
- B. 自动关闭实现了 AutoCloseable 的资源
- C. 捕获所有异常
- D. 提升运行速度

答案：B
解析：编译器会生成 finally 中的关闭逻辑，避免资源泄漏，优于手写 try-catch-finally。详见《01-入门篇/04-异常-IO-反射-注解.md》

### 6.（Java基础·中）关于 String 不可变，正确的解释是？
- A. String 是可变的，只是习惯上不改
- B. 频繁拼接字符串应优先用 String
- C. String 类被 final 修饰、内部数据私有且不暴露修改方法
- D. String 是基本数据类型

答案：C
解析：不可变带来安全性、字符串常量池复用、hashCode 可缓存；频繁拼接用 StringBuilder。详见《01-入门篇/02-面向对象与核心类.md》

### 7.（集合·中）JDK 1.8 中 ArrayList 首次 add 时容量扩到 10，此后每次扩容为原来的？
- A. 2 倍
- B. 1.2 倍
- C. 3 倍
- D. 1.5 倍

答案：D
解析：newCapacity = oldCapacity + (oldCapacity >> 1)，即 1.5 倍向下取整。详见《01-入门篇/03-集合与泛型.md》

### 8.（集合·中）HashMap（JDK 1.8）中链表转红黑树的条件是？
- A. 链表长度 ≥ 8 且数组长度 ≥ 64
- B. 链表长度 ≥ 8 即可
- C. 链表长度 ≥ 16
- D. 元素总数 ≥ 64

答案：A
解析：数组长度不足 64 时优先扩容而不是树化；红黑树退化回链表的阈值是 6。详见《01-入门篇/03-集合与泛型.md》

### 9.（集合·易）HashSet 判断元素是否重复依赖的方法是？
- A. 仅 equals
- B. hashCode 与 equals
- C. 仅 ==
- D. compareTo

答案：B
解析：先用 hashCode 定位桶，再在桶内用 equals 精确比较，两者必须一起重写。详见《01-入门篇/03-集合与泛型.md》

### 10.（集合·易）下列集合中线程安全的是？
- A. ArrayList
- B. HashMap
- C. Vector
- D. LinkedList

答案：C
解析：Vector 方法用 synchronized 修饰；现代并发场景更推荐 ConcurrentHashMap 或 CopyOnWriteArrayList。详见《01-入门篇/03-集合与泛型.md》

### 11.（集合·易）用 for-each 遍历 ArrayList 时直接调用 list.remove(o)，通常会？
- A. 正常删除
- B. 编译错误
- C. 静默删除所有元素
- D. 抛出 ConcurrentModificationException

答案：D
解析：fail-fast 机制检测到 modCount 被修改即抛异常；正确做法是 Iterator.remove() 或 removeIf。详见《01-入门篇/03-集合与泛型.md》

### 12.（并发·易）直接调用线程对象的 run() 而不是 start()，结果是？
- A. 在当前线程中作为普通方法执行
- B. 创建新线程执行
- C. 抛出异常
- D. 永久阻塞

答案：A
解析：只有 start() 会让 JVM 创建新线程并调用 run()；直接调 run() 与普通方法调用无异。详见《02-进阶篇/01-多线程与并发编程.md》

### 13.（并发·易）volatile 能保证的是？
- A. 原子性
- B. 可见性与有序性
- C. 原子性与可见性
- D. 原子性、可见性、有序性都保证

答案：B
解析：volatile 保证可见性和禁止指令重排，但 i++ 这类复合操作仍需 synchronized 或原子类。详见《02-进阶篇/01-多线程与并发编程.md》

### 14.（并发·中）线程池提交任务后的处理顺序是？
- A. 直接创建线程直到最大线程数
- B. 核心线程 → 阻塞队列 → 非核心线程 → 拒绝策略
- C. 先入队列再创建核心线程
- D. 顺序随机

答案：B
解析：先占满核心线程，队列满了才扩非核心线程，到 max 后触发拒绝策略——这也是 FixedThreadPool 无界队列堆积 OOM 的根源。详见《02-进阶篇/01-多线程与并发编程.md》

### 15.（并发·中）synchronized 锁升级的正确顺序是？
- A. 重量级锁 → 轻量级锁 → 偏向锁
- B. 轻量级锁 → 偏向锁 → 重量级锁
- C. 偏向锁 → 轻量级锁 → 重量级锁
- D. 不存在锁升级

答案：C
解析：JVM 按竞争激烈程度逐步升级且不可逆，目的是减少无竞争场景的开销。详见《02-进阶篇/01-多线程与并发编程.md》

### 16.（并发·中）ThreadLocal 可能内存泄漏的根本原因是？
- A. key 是强引用
- B. value 是弱引用

答案：D
解析：线程池中线程长期存活，ThreadLocalMap 的 value 无法自动回收，用完必须调用 remove()。详见《02-进阶篇/01-多线程与并发编程.md》

### 17.（并发·易）以下哪个不是 ThreadPoolExecutor 的拒绝策略？

### 18.（JVM·中）以下运行时区域中，规范规定不会抛出 OutOfMemoryError 的是？
- A. 堆
- B. 程序计数器
- C. 虚拟机栈
- D. 元空间

答案：B
解析：程序计数器是唯一没有规定任何 OOM 情况的区域；栈是 StackOverflowError，堆和元空间都会 OOM。详见《02-进阶篇/02-JVM核心.md》

### 19.（JVM·易）判断对象是否可回收，主流商用虚拟机采用？

答案：C
解析：可达性分析解决了引用计数法的循环引用问题；GC Roots 包括栈帧局部变量、静态变量、常量、JNI 引用等。详见《02-进阶篇/02-JVM核心.md》

### 20.（JVM·中）双亲委派机制的主要作用是？

### 21.（JVM·中）关于 G1 收集器，下列说法正确的是？

解析：从节点上报 master_repl_offset，只要在 backlog 范围内就只补差额；否则重新 fork 做全量同步，大内存实例 fork 会带来毫秒级阻塞。详见《05-中间件篇/01-Redis.md》

### 125.（Redis·难）分布式锁"误删别人的锁"发生在：客户端 A 持锁后长时间 GC 停顿，锁＿＿＿后被 B 获取，A 恢复后直接 DEL 删掉了 B 的锁；解法是 value 存唯一标识并加＿＿＿原子校验删除。
答案：过期；Lua／lua／lua脚本
解析：判断与删除必须是两步，普通代码非原子；Redisson 用看门狗续期避免过期，用 Lua 校验持有者避免误删。详见《05-中间件篇/01-Redis.md》

### 126.（MySQL·难）RR 下事务第一次快照读时生成 ReadView，此后＿＿＿（填"复用/每次重新生成"）；RC 则是每次＿＿＿都重新生成。
答案：复用；查询／select／快照读
解析：ReadView 记录了生成时仍活跃的事务 ID 集合，据此判断版本可见性；复用同一份快照正是"可重复读"的实现手段。详见《03-数据库篇/02-索引-事务-锁与调优.md》

### 127.（操作系统·中）Linux 下递归搜索目录内所有文件的文本内容，常用 grep 的 ＿＿＿ 参数（写作两个字母或长选项）。
答案：-r／-R／--recursive
解析：`grep -rn "关键词" 目录` 会递归并显示行号；-R 与 -r 的差别是对符号链接的处理，管道配合 `| head` 控制输出量。详见《02-进阶篇/04-开发工具链-Git-Maven-Linux.md》

### 128.（工具链·中）要确认本机某端口是否被进程监听，常用命令是 ＿＿＿（含参数）。
答案：ss -lntp／ss -lnt／netstat -anp／lsof -i:端口
解析：-l 只看 LISTEN、-n 不做 DNS 反解、-t 只看 TCP、-p 显示进程；ss 比 netstat 更快，容器里没 ss 时可用 lsof。详见《02-进阶篇/04-开发工具链-Git-Maven-Linux.md》

### 129.（Redis·难）ZSET 在元素较少、分值较短时用＿＿＿编码存储；超过阈值后改为跳表＋字典表双结构，其中跳表的作用是支持按分数区间 O(logN) 查找。
答案：ziplist／压缩列表／listpack／快速列表
解析：小 ZSET 用 ziplist/listpack 连续内存省开销；变大后拆成 skiplist（按 score 范围与排名查找）+ dict（按成员 O(1) 取分数）。详见《05-中间件篇/01-Redis.md》

## 判断题

### 130.（并发·易）volatile 可以保证 i++ 这类复合操作的原子性。
- A. 正确
- B. 错误

答案：B
解析：volatile 只管可见性与有序性，i++ 是"读-改-写"三步，并发下仍会丢更新，需要 synchronized 或 AtomicInteger。详见《02-进阶篇/01-多线程与并发编程.md》

### 131.（集合·易）HashMap 的 key 允许为 null。
- A. 正确
- B. 错误

答案：A
解析：JDK 1.8 允许一个 null 键（固定放在 0 号桶）；而 Hashtable 与 ConcurrentHashMap 的 key、value 都不允许为 null。详见《01-入门篇/03-集合与泛型.md》

### 132.（Java基础·中）`"a|b".split("|")` 能正确按竖线切成两个元素，不需要转义。
- A. 正确
- B. 错误

答案：B
解析：split 的参数是正则，竖线表示"或"，结果是每个字符被空匹配切开；必须写成 split("\\|")。详见《01-入门篇/02-面向对象与核心类.md》

### 133.（并发·中）synchronized 修饰静态方法时，锁的是该类的 Class 对象。
- A. 正确
- B. 错误

答案：A
解析：静态方法没有 this，锁的是 Class 对象，与实例锁互不影响——同一类里静态与实例同步方法可以并发进入。详见《02-进阶篇/01-多线程与并发编程.md》

### 134.（集合·中）重写 equals 而不重写 hashCode，程序一定会抛出异常或明显出错。
- A. 正确
- B. 错误

答案：B
解析：不放进哈希容器时逻辑上看不出问题，所以更隐蔽；一旦用作 HashMap 键或 HashSet 元素，就会重复存、get 不到。违反的是约定而非必然崩溃。详见《01-入门篇/02-面向对象与核心类.md》

### 135.（框架·易）MyBatis 的 #{} 最终会被编译成 JDBC 的预编译占位符 ?。
- A. 正确
- B. 错误

答案：A
解析：#{} 由 PreparedStatement 用 setXxx 绑定参数，SQL 结构在编译期确定，因此能防注入。详见《04-框架篇/03-MyBatis.md》

### 136.（Redis·中）Redis 6.0 的多线程只用于网络 IO 与协议解析，命令的执行仍然是单线程。
- A. 正确
- B. 错误

答案：A
解析：多线程解决的是网络读写瓶颈；命令在单线程中串行执行，因此单条命令的原子性依旧成立，Lua 脚本也据此工作。详见《05-中间件篇/01-Redis.md》

### 137.（消息队列·中）Kafka Topic 增加分区数后，同一个 key 的消息可能被路由到与历史不同的分区。
- A. 正确
- B. 错误

答案：A
解析：分区路由是 hash(key) % 分区数，分区数一变映射就变；需要严格顺序的业务要评估扩容影响或改用新 Topic。详见《05-中间件篇/03-Kafka.md》

### 138.（MySQL·中）在默认 RR 隔离级别下，MySQL 已经彻底杜绝了幻读，任何写法都不会出现。
- A. 正确
- B. 错误

答案：B
解析：快照读靠 MVCC、当前读靠临键锁各自避免幻读，但"先快照读、再被别的事务插入、再当前读/更新"这类混用场景仍会看到幻影行。详见《03-数据库篇/02-索引-事务-锁与调优.md》

### 139.（框架·中）Spring 事务传播行为 REQUIRED 表示：当前有事务就加入，没有就新建一个。
- A. 正确
- B. 错误

答案：A
解析：这是默认值；REQUIRES_NEW 会挂起当前事务另开一个，NESTED 用保存点，SUPPORTS 无事务则非事务执行。详见《04-框架篇/01-Spring核心.md》

### 140.（框架·中）@Transactional 默认会对所有抛出的 Exception（含受检异常）回滚。
- A. 正确
- B. 错误

答案：B
解析：默认只对 RuntimeException 和 Error 回滚，受检异常需要 rollbackFor = Exception.class 才回滚——这是最常见的"事务没回滚"原因。详见《04-框架篇/01-Spring核心.md》

### 141.（单元测试·中）为提高覆盖率，单元测试应优先直接测试私有方法。
- A. 正确
- B. 错误

答案：B
解析：私有方法是实现细节，直接反射测试会让重构寸步难行；应通过公共入口的行为测试间接覆盖，若难测则说明该方法该拆出去了。详见《04-框架篇/05-单元测试与工程质量.md》
